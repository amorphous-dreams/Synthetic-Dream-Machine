## Claude Adapter Surface

- Keep this file thin.
- Add only Claude-specific customizations here.
- The seed seats by reference (lar:///ha.ka.ba/lares/docs/pono/seed-seat): `.claude/noosphere-boot` links to the boot seed, since an import loads a file by its name and a `.mem` loads nothing. Explore and Plan skip CLAUDE.md, so `.claude/agents/{Explore,Plan}.md` carry the seed as a projection the root build writes. `lares repo tend` keeps the checkout's seat and `lares home tend` the operator's own rule, which `.claude/settings.json` excludes inside the clone; `tools/repo-tunnel-witness.sh` reads the checkout.
- `daemonBagsDir()` resolves `LAR_BAGS` → `config.resources.bags` → `<LAR_ROOT>/bags` → `<repo>/bags`, and that dir names the CANON SOURCE. The disk mirrors split by origin (`projectionRoots`): a bag whose dir stands in the canon source projects back into it, with its wiki under `wikis/` beside it; house-minted bags, the private planes and the `kahua-<tag>` folders project under the state root (`--root`/`LAR_ROOT`). With neither set, a fresh clone boots REPO-RELATIVE by design.
- So the tracked tree takes writes in exactly two cases: (1) a bare in-tree boot (no `LAR_ROOT`); (2) any boot whose canon source resolves to the checkout's `bags/` (`LAR_BAGS=<checkout>/bags`, or a config naming it), where live edits to every canon-sourced bag (lares, lararium, crossroads, any dir standing there) land in the tracked `bags/` and `wikis/` by design, as source-control write-back, even under a scratch `LAR_ROOT`. A scratch `LAR_ROOT` with no `LAR_BAGS` and no config naming the checkout stays isolated: store, canon source and every mirror move under it (genesis too; `LAR_GENESIS` overrides). Isolate every dev/smoke boot that way; never boot in-tree bare. e2e: a scratch `LAR_ROOT` per vessel, no global `LAR_BAGS`. `tools/tree-clean-witness.sh` reads any write into the tracked tree as red.
